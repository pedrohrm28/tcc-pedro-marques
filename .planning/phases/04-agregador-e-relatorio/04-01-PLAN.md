- D-01: `metricas_token(gold_seqs, pred_seqs)` recebe DUAS listas de listas de tags (uma lista por
  sentença, alinhadas posição-a-posição). Retorna `(linhas, micro)`:
  `linhas = [(classe, p, r, f1, suporte), ...]` ordenado por classe; `micro = (micro_p, micro_r, micro_f)`.
  Definições: tp[c] quando g==p==c; fp[p] e fn[g] quando g!=p. suporte = tp[c]+fn[c]. Divisões por
  zero -> 0.0. ISSO É IDÊNTICO ao legado (l.149-170) — copiar verbatim.
- D-01 (REFATORAR): `metricas_entidade(gold_seqs, pred_seqs)` usa seqeval, que recebe LISTA DE LISTAS
  de tags IOB por sentença (ex `[["O","B-geo","I-geo"], ["B-per","I-per"]]`). O legado IMPRIME o
  classification_report e as métricas (l.181-185). O NOVO deve RETORNAR um dict, ex:
  `{"precisao": float, "cobertura": float, "f1": float, "por_tipo": {tipo: {"precisao","cobertura","f1","suporte"}}}`.
- seqeval API (`seqeval.metrics`): `precision_score(y_true, y_pred)`, `recall_score(...)`,
  `f1_score(...)` (todos retornam float, micro por padrão); `classification_report(y_true, y_pred,
  output_dict=True)` retorna dict por-tipo (chaves = tipos de entidade SEM o prefixo IOB, ex "geo",
  "per"; cada valor tem "precision"/"recall"/"f1-score"/"support"). seqeval JÁ está em requirements.txt
  (linha 2) mas pode não estar instalado no ambiente — `pip install seqeval` antes de rodar os testes.

  nível de entidade — `metricas_entidade` é chamado SÓ para NER.
